# CLAUDE.md — навигатор по проекту clave

Этот файл — первое, что читает агент. Здесь собраны НЕОЧЕВИДНЫЕ тонкости и грабли,
на которых легко сломать проект. Структуру кода агент увидит сам — тут то, чего в коде
не видно.

---

## 0. Что такое clave

Локальный **TUI-оркестратор на Rust** (v0.3.0, MIT, edition 2021). Связывает CLI
`claude` и `codex` как агентов в один цикл. Зависимости минимальны: `crossterm 0.29`,
`ratatui 0.30`, `serde_json`, `unicode-width`, на unix — `libc`. Никаких async-рантаймов.

Режимы: **чат**, **план** (встроенный движок `spec-clave` вшит в бинарь), **тандем**
(Executor=Claude + Critic=Codex спорят до консенсуса → исполнение → ревью → правка).

## 2. Тулчейн (иначе `cargo: command not found`)

`cargo`/`rustc` лежат в `~/.cargo/bin` и НЕ в PATH сессии. В начале любой команды:

```sh
export PATH="$HOME/.cargo/bin:$PATH"
```

## 3. ГЕЙТ: без него ничего не отгружается

Перед КАЖДОЙ отгрузкой прогнать ВСЁ и убедиться, что зелено. `exit 0` — НЕ доказательство:
смотреть на строку `test result: ok. N passed`, а не на код возврата.

```sh
# PATH 1 — обычный
cargo test --bin clave

# PATH 2 — «CI без провайдеров»: пустое окружение без claude/codex в PATH.
# Ловит скрытые зависимости от установленных CLI. ОБЯЗАТЕЛЕН — на нём падало то,
# что PATH 1 пропускал.
env -i PATH="$HOME/.cargo/bin:/usr/bin:/bin:/usr/sbin:/sbin" HOME="$HOME" cargo test

cargo clippy --bin clave --all-targets   # проект живёт на -D warnings, любое = красный
cargo fmt --check                        # `fmt --check | tail` ВРЁТ про exit — смотри вывод
```

## 4. Две ветки — САМОЕ КРИТИЧНОЕ

**`main` = чистый продукт. `develop` = продукт + инструменты саморазработки (self-dev).**
Вся разница main↔develop — самопиловая. develop живёт в **worktree**:
`.claude/worktrees/clave-dev-headless`.

### Продуктовое изменение (обе ветки)

```sh
WT=.claude/worktrees/clave-dev-headless
# 1) коммит на main, прогнать гейт
# 2) перенести НА develop ИЗ worktree (не переключать ветку в основном каталоге!):
git -C "$WT" cherry-pick -x <sha>
# 3) прогнать гейт (оба PATH) УЖЕ на develop — там собирается и headless-раннер
# 4) push обе ветки
```

### Что живёт ТОЛЬКО на develop и НИКОГДА не едет в main

Скрытый вход супервайзера `--run <режим>` → `Launch::Headless` → `crate::headless::run_headless`,
каталоги `tools/clave-dev/`, `scripts/selfdev/`, файлы `src/headless.rs`, `src/app/dev.rs`,
проводка `mod headless;`/`clave_dev`/`CLAVE_DEV`. Собранный из такого дерева релиз унёс бы
пользователям спрятанный пульт самопиления.

### Страж прода

`.git/hooks/pre-push` (локальный, **untracked** — его не видно сканом репозитория).
Смотрит РЕЗУЛЬТИРУЮЩЕЕ ДЕРЕВО пушимого коммита (не дифф) для `main` **и тегов версий**
(`vX.Y.Z` — по ним cargo-dist публикует релиз с любой ветки, мимо стража main).
Блокирует, если в дереве есть self-dev пути или проводка. `WIRING_RE` (`clave_dev` и т.п.)
сканит **только `src/`** — поэтому корневые доки (этот файл) стража не задевают.
Осознанный обход: `git push --no-verify`. Реальный резерв — только этот хук; CI-воркфлоу
лишь бэкстоп.

### Грабли cherry-pick (проверено болью)

- `git add -A <pathspec>` НЕ стейджит удаление файла при dir-split (`src/x.rs` → `src/x/`):
  pathspec `src/x` матчит каталог, не файл. Коммит уедет с ОБОИМИ → `file for module found
  at both`. Делай `git rm src/x.rs` явно ИЛИ `git add -A` без pathspec; проверь
  `git ls-tree --name-only HEAD src/ | grep x`.
- cherry-pick структурного изменения файла на develop **молча сносит** develop-only склейку
  в этом файле (напр. `Launch::Headless` в `runtime/mod.rs`). Рабочее дерево соберётся на
  кеше, но `run_headless` осиротеет. ВСЕГДА после cherry-pick гонять `clippy` на develop;
  dead-code warning → вернуть склейку **develop-only** коммитом (в main не идёт).
- Интерактивная блокировка воркера ВЕШАЕТ headless-раннер — решения предзагружать.

## 5. Карта модулей (`src/`)

Всё реэкспортится в crate root (`pub(crate) use <mod>::*` в `main.rs`), поэтому вызовы
плоские. Подмодуль видит siblings через `use crate::*` (если модуль реэкспортится в root:
worker/storage/ui/app) или `use super::*` (runtime — в root НЕ реэкспортится).

- **`worker/`** — провайдеры (`claude`/`codex`: запуск CLI, парс активности), `chat`,
  `tandem` (оркестрация дебатов), `prompts`, `engine` (вшитый `spec-clave`), `process`
  (группы процессов, kill-tree, idle-таймауты), `response` (парс ответа/использования).
- **`runtime/`** — вход (`launch_for`/`main_entry`), event loop (`run_app`), диспетчер
  клавиш (`handle_key`) + обработчики по концернам (`input`/`onboarding`/`plugins`/`dialogs`),
  `terminal` (restore/panic), `welcome`.
- **`app/`** — состояние `App` и его методы (команды, события, чаты, runs, ask). Много
  `impl App` — методы, не свободные функции.
- **`ui/`** — отрисовка на **ratatui-виджетах** (безопасно править).
- **`render.rs`** — ⚠️ см. §6.
- **`storage/`** — персистентность: `config` (конфиг+история, атомарная запись),
  `chats` (транскрипты/сводки/заголовки, изолированы по каталогу запуска), `mod`
  (пути состояния, кодирование полей).
- `model/`, `plugins/`, `auth.rs`, `input/`, `prelude`.

## 6. `render.rs` — ХРУПКИЙ ручной рендерер

Живую ленту рисует НЕ ratatui, а **ручной курсорный diff-рендерер** (`RenderState::render_to`:
отслеживает `prev_height`, ходит `MoveUp`/`Clear`). Работает на ОСНОВНОМ экране (не alt-screen),
флашит в нативный скроллбэк. Высокие живые блоки рассинхронивают курсор → залипшие лоадеры и
стёртый текст. Любую правку render.rs проверять НА ЖИВОМ запуске, не только тестами.
Владелец просил render трогать в последнюю очередь.

## 7. Тандем: тонкости

Дебаты Executor↔Critic до `TANDEM: CONSENSUS`, затем исполнение → ревью → правка. Критик
намеренно напромтлен на **сходимость**: отделяет БЛОКЕРЫ от не-блокеров, знает бюджет раундов,
не крутит перфекционизм вечно (иначе на туманной задаче мог висеть часами). NEED_INPUT ставит
паузу (текст или кнопки-варианты для закрытых вопросов). Маркеры из ленты стрипаются, статусы
человеческие. Режим чата (в т.ч. тандем) переживает перезапуск. Диагностировать тандем удобнее
из CLI-раннера (в TUI причина не видна) — но это develop-инструмент.

## 8. Кампания декомпозиции (идёт)

Файлы >500 строк дробятся по концернам (Rust module discipline). Уже разобраны: `worker`
(было 3996), `runtime` (3247), `storage` (1438), `ui/effort` (1494). Осталось ~16 файлов
>500 (см. auto-memory `file-decomposition-campaign`). Принцип: тесты переезжают ВМЕСТЕ со
своим кодом; общие тест-хелперы выносятся в `#[cfg(test)] pub(crate) mod testkit/keytest`,
подмодули импортируют его явно. `render.rs` — отложен (см. §6). Инкремент = один файл,
полный гейт, отгрузка в обе ветки, дерево НИКОГДА не сломано.

## 9. Разное

- `/export` в TUI ПЕРЕЗАПИСЫВАЕТ файл целиком (не аппендит) — сравнивать содержимое/mtime,
  а не число строк.
- Переустановка бинаря НЕ подменяет уже запущенный процесс: работающий clave держит старый
  код до перезапуска.
- Владелец на macOS, репозиторий приватный, пока для себя.
