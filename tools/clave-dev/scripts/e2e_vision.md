# clave-dev Фаза 2 — e2e vision (запускает пользователь на macOS)

Реальный proof зрения выполняется на твоей машине: нужен GUI Terminal.app и системные
разрешения, которых нет в headless-сессии (см. спеку §1). Юнит-логика (нормализация вердикта,
разрешение окна, fail-safe захвата) уже проверена автотестами; здесь — настоящий прогон.

## 1. Разрешения (one-time)

System Settings → Privacy & Security:
- **Accessibility** — включить для приложения, из которого запускаешь (Terminal.app и/или раннер),
  иначе System Events не сможет слать клавиши.
- **Screen Recording** — включить там же, иначе `screencapture` вернёт пустой/чёрный кадр
  (clave-dev это детектит и выдаёт **блокирующий** вердикт, не «pass»).

## 2. Профиль Terminal.app (детерминизм среды, §4)

Создай профиль `clave-dev` (Terminal → Settings → Profiles): фикс. шрифт (SF Mono 13),
тема без прозрачности (opacity 1.0), размер под `default_profile()` (100×30). Профиль задаётся
флагом `--terminal-profile clave-dev`; среда логируется в stderr в начале прогона.

## 3. Канал зрения (§3) — ПОДКЛЮЧЁН, два бэкенда

Открытый вопрос спеки («умеет ли текущий `claude` CLI принимать PNG») **закрыт положительно**:
CLI читает изображение по пути своим Read-инструментом. Поэтому есть два канала:

**`--vision claude-cli` (рекомендую; ключ НЕ нужен).** Использует уже авторизованный `claude` CLI.
Ничего экспортировать не надо — работает там же, где живёт сам clave.

**`--vision claude` (прямой image-API).** Нужен ключ:
```bash
export ANTHROPIC_API_KEY="sk-ant-..."
export CLAVE_VISION_MODEL="claude-sonnet-5"    # опц.
```

Если канал недоступен — `available()` вернёт False, clave-dev честно печатает «зрение выключено»
и идёт текст-онли (Фаза 1), не выдавая ложный pass. Ответ парсится `extract_verdict_json`+
`parse_verdict` (fail-safe: непарсящийся ответ → блокирующий вердикт).

### Предусловия окружения (грабли, найденные вживую)

- **pyobjc** (для CGWindowID и декода кадра): ставится только современным pip —
  `python3 -m pip install --upgrade pip && pip install pyobjc-framework-Quartz`.
  На старом pip сборка `pyobjc-core` из исходников падает.
- **Песочница**: `screencapture` требует доступа к оконному серверу. Из sandbox-окружения он
  отвечает «could not create image from display» даже при выданных TCC-правах — гонять probe
  нужно вне песочницы.
- **Локализованная macOS**: AppleScript адресует приложение как `Terminal`, а CGWindowList отдаёт
  локализованное имя (`Терминал`). Резолв окна поэтому матчит по УНИКАЛЬНОМУ титулу-nonce,
  владелец — лишь мягкий фильтр (см. `window_resolve.py`).

## 4. Прогон

```bash
export PATH="$HOME/.cargo/bin:$PATH"
cd <repo>/tools/clave-dev
python3 -m clave_dev "почини срез футера у правой стенки" \
  --repo <repo> --known-good <ветковый clave с --run> \
  --build-profile debug --vision claude --terminal-profile clave-dev \
  --severity-threshold medium --max-rounds 3
```

### 4b. Точечный vision-probe (рекомендую для proof pass=false/true)

Без полной петли — один скриншот + вердикт, быстро. Собери clave ветки (`cargo build`), затем:

```bash
cd <repo>/tools/clave-dev
# узкое окно → ожидаем pass=false (срез у правой стенки)
python3 -m clave_dev.vision_probe <repo>/target/debug/clave \
  --width 380 --height 600 --terminal-profile clave-dev
# нормальное окно → ожидаем pass=true
python3 -m clave_dev.vision_probe <repo>/target/debug/clave \
  --width 900 --height 640 --terminal-profile clave-dev
```

Печатает JSON-вердикт (`pass`, `issues`, `failed_required`, `open_critique`) и код выхода 0/1.

## 5. Ожидаемый результат (критерии proof)

**Как получить контролируемо «битый» кадр** (без правок кода): сузь окно Terminal.app до
минимальной ширины (или уменьши размер/увеличь шрифт в профиле `clave-dev`) — футер и правый
край контента налезут на стенку, ровно тот класс ambiguous-width среза. «Чистый» — нормальная
ширина. Сравнение узкое/нормальное и даёт пару pass=false / pass=true.

- **Битый UI** (заведомо срезанный футер): vision-вердикт `pass=false`, среди `checklist_results`
  провален required-пункт «текст не касается правой границы» и/или есть `high`-issue про правый край;
  супервайзер **не** сходится, фидбэк с описанием уходит агенту.
- **Чистый UI**: `pass=true`, петля сходится (если и проверки, и текстовые assertions зелёные).
- **Нет Screen Recording**: блокирующий вердикт «кадр пустой/чёрный», не ложный pass.
- **Окно не найдено/неоднозначно**: `WindowNotFoundError` с перечислением кандидатов.

## 6. Результат proof — ПРОЙДЕН (прогнано 2026-07-12, реальный Terminal.app)

Зрение прогнано на настоящем macOS-рендере через `--vision claude-cli`. A/B на одном и том же
окне 1100×700 и одном и том же промпте, две сборки clave:

| Сборка | Вердикт |
|---|---|
| **без margin-фикса футера** (ветка от `23bd9dc`) | `pass=false`; `failed_required: ["Текст не касается правой границы"]`; issue: «правый сегмент статус-строки `roles claude>code` прижат к правому краю без отступа, в отличие от левого» |
| **с фиксом** (`budget = width.saturating_sub(2)`) | `pass=true`; `issues: []`; «Дефектов рендеринга нет» |

Плюс узкое окно 380×600 на битой сборке → `pass=false` с провалом **обоих** required-пунктов
(«текст не касается правой границы», «нет обрезанных глифов») и `high`-issue про перенос,
упирающийся в правый край.

**Вывод.** Vision-слой ловит именно тот класс дефектов, ради которого строился (срез у правой
стенки в реальном рендере Terminal.app — то, чего pty-сетка структурно не видит), и корректно
отличает битую сборку от починенной. Заодно это независимое машинное подтверждение, что
margin-фикс футера действительно устраняет дефект.

## 7. Профиль Terminal для самозакрытия окна (обязательно для зрения в /dev)

Окно Terminal **нельзя закрыть снаружи** — проверено на живой системе: AppleScript `close`
молча не срабатывает, `close` вкладки Terminal не понимает (-1708), а System Events на ввод
(keystroke/клик по крестику) из нашего контекста не действует вовсе. Поэтому окно
визуального прохода должно закрыть **себя само**.

Как это устроено: команда запуска заканчивается `; exit`, вкладке назначается профиль
`clave-dev`, у которого «при выходе из shell — закрыть окно». Клавиша к разгадке —
значение ключа:

```
shellExitAction = 2   →  закрыть окно      ← нужно нам
shellExitAction = 0/1 →  окно остаётся
```

Профиль создаётся один раз (Terminal → Настройки → Профили, либо правкой
`~/Library/Preferences/com.apple.Terminal.plist`), после чего **Terminal нужно перезапустить** —
работающий новый профиль не видит. Preflight проверяет наличие профиля и отказывается
стартовать без него: иначе за каждый раунд копилось бы окно-мусор.
